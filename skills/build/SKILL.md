# Cervart build and verification

You work autonomously and do not dispatch sub-agents. Make focused code changes when the task requires them, then verify the result. Never commit, push, switch branches, merge, or change git state.

Read `CODESTYLE.md`, `AGENTS.md`, and the relevant files under `docs/`.

## Inputs

- The task or plan, with the files that are expected to change.
- The verification scope: focused paths for a small change, the whole project for a cross-cutting one.

## Process

1. Read the task, the plan, and the affected modules before editing.
2. Follow the project architecture: FSD layers, public API through `index.ts`, `_ui/` is private, relative imports inside `entities` and `features`, features do not call the API of other features, and the root element of a component is `ComponentWrapper`. Details: `architecture`.
3. Error handling: `parseApiError` → `showToast.error` → `throwException`.
4. State: RTK Query for server data, `sessionState.use*()` for stable UI selections, `pageNavigationState.use*()` for navigation, local `useState` for local UI.
5. Do not leave placeholders or stubs such as `// TODO`.
6. Never edit `.env.development.local` or any other `.env*`/`*.local` file. The development env file is generated by `scripts/gen_env_*.js`.
7. Do not start long-running dev servers (`pnpm run-*`).
8. Run the verification matrix below.
9. If the task asks for a plan, write it to `.tmp/plans/<task-slug>.md` — the standard plans folder shared with `plan`; never to `.opencode/plans/`.

## Verification matrix

| Change                                            | Commands, in order                                                                                   |
| ------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Any `src/**` change                               | `pnpm exec vitest run <changed paths>` → `pnpm lint` → `pnpm typecheck` → `pnpm build` → `pnpm test` |
| Docs, skills, agent config only                   | `pnpm lint` → `pnpm typecheck` → `pnpm test`                                                         |
| Shared API, RTK Query endpoints, entities helpers | focused Vitest for the module → `pnpm lint` → `pnpm build` → `pnpm test`                             |
| Build configuration, env generators, CI           | `pnpm build` → `pnpm test`                                                                           |
| Nothing changed in `src/`                         | `pnpm lint` → `pnpm typecheck` → `pnpm test`                                                         |

Rules:

- A command counts as passed only with exit code 0. Paste the exact commands and their results into the report.
- `pnpm build` already runs `pnpm typecheck`; still run typecheck when the matrix lists it, so a type error is reported separately from a bundling error.
- Focused Vitest runs never replace the full `pnpm test` before the final report.
- If a check fails, fix the cause and rerun the whole row of the matrix.

## Output

`DONE` or `BLOCKED` with a short summary of the changes, the exact commands run, and their results. Answer the user in Russian.

## BLOCKED

- A verification command fails and the cause is outside the allowed edit scope.
- The task requires editing `.env*` or `*.local`.
- A long-running dev server is required to proceed.
- The repository state contradicts the plan (for example, unrelated dirty files).

## Out of scope

Sub-agents, commits, pushes, branch switches, merges, MR creation, deploys, and dev servers. Architecture rules: `architecture`; test rules: `testing`.
